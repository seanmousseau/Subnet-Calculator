## Cross-cutting design decisions (locked)

1. **Test rig drains admin state at suite setup** — no per-run `docker compose down -v`. Every later PR depends on this floor being deterministic.
2. **PHPCS covers `admin/`** via `.phpcs-admin.xml` (template-aware ruleset). New admin code must lint cleanly under this ruleset from PR2 onwards.
3. **UI surfaces use the existing tool-drawer pattern.** No new card-style result blocks. Anything that produces a result + has a form goes in a tool drawer with a `tool-trigger` toolbar entry.
4. **`ui-ux-pro-max` consulted before AND after** every UI-bearing task. Consultant's spec captured verbatim in the PR description; deviations fixed in the same task.
5. **No new colour primitives or CSS tokens.** Reuse `--color-bg`, `--color-surface`, `--color-text`, `--color-border`, `--color-accent`, `--color-btn-text`, plus the success/warning/error fg semantics already in the v2.9.0 style guide.
6. **`documentation` skill for every doc edit.** No raw `mkdocs build` or freehand README changes — every doc-touching commit goes through the skill once.
7. **Memory MCP observation** at the close of every task. Required fields: factual sentence, files/functions touched, git short SHA, test result.
8. **Common look and feel** — every task references the v2.9.0 style guide and the v3.0.0 living doc's design-language notes; deviations are blockers, not nits.

### Task 2 — 2026-05-04 — #326 PHPCS admin scope (template-aware ruleset)
**Status:** ✅ Done

Delivered:
- New `.phpcs-admin.xml` ruleset rooted at `Subnet-Calculator/admin/`,
  extending PSR-12 with five targeted relaxations that reflect the
  template-style nature of admin pages (mixed PHP controller + HTML output):
  - `Generic.Files.LineLength` excluded — HTML attribute soup and i18n
    strings legitimately exceed 120 chars; wrapping hurts readability.
  - `PSR1.Files.SideEffects` excluded — every admin page IS a side-effect
    front controller (boots SQLite, validates session, emits HTML).
  - `Squiz.WhiteSpace.ScopeIndent` excluded — HTML/PHP transitions anchor
    to outer markup, not the PHP scope depth, and the sniff cannot tell
    the difference.
  - `Squiz.WhiteSpace.ScopeClosingBrace` excluded — single-line
    `<?php if (...) : ?>...<?php endif; ?>` inline-template rows trip on
    the `endif` keyword sharing its line with HTML output.
  - `Squiz.WhiteSpace.ControlStructureSpacing` and
    `PSR12.ControlStructures.ControlStructureSpacing.FirstExpressionLine`
    excluded — alternative-syntax `<?php else : ?>` branches with HTML
    breathing room and multi-line auth-predicate wrapping respectively.
  - `Generic.WhiteSpace.ScopeIndent` retained with `exact=false` (set as
    a defensive secondary; the full exclude above takes precedence).
- `.github/workflows/php.yml` now runs the new ruleset as a second PHPCS
  step on every PR, immediately after the existing PSR-12 invocation. Step
  is static (no `${{ ... }}` interpolation) per security policy.
- `CLAUDE.md` Development block documents the new admin lint command
  alongside the existing PSR-12 invocation.
- Admin files (`keys.php`, `audit.php`, `totp.php`, `totp-verify.php`,
  `_wizard.php`, `_test-drain.php`) needed **zero** behaviour or markup
  changes — the ruleset relaxations cover every offender produced by the
  template-style mixing. No `// phpcs:ignore` comments added.

### Task 1 — 2026-05-04 — #324 drain admin state at test-suite setup
**Status:** ✅ Done

Delivered:
- New `admin/_test-drain.php` endpoint, fail-closed: `404` when
  `PHPUNIT_TEST_DRAIN_TOKEN` env is unset (production case), `403` on token
  mismatch (timing-safe `hash_equals()`), `200` on match — truncates
  `api_keys`, `admin_audit`, `admin_recovery_codes`, and clears `sess_*`
  files in the resolved session directory (basename + realpath confined,
  symlink-safe). Tables that do not yet exist are skipped silently.
- `Makefile` generates a fresh per-run token via
  `php -r 'echo bin2hex(random_bytes(16));'` and exports it; never lands
  on disk, never committed. Token is regenerated every `make test-docker`.
- `docker-compose.yml` forwards `PHPUNIT_TEST_DRAIN_TOKEN` to BOTH the
  `webapp` and `playwright-tests` services (interpolated with empty-string
  default — empty in plain `docker compose up` so the endpoint stays inert).
- `Dockerfile` adds `PassEnv PHPUNIT_TEST_DRAIN_TOKEN` to apache2.conf so
  PHP's `getenv()` sees the variable through mod_php.
- `testing/scripts/playwright_test.py` adds `_drain_admin_state()` helper
  invoked once in `main()` before any admin test, plus a new
  `test_admin_drain_endpoint_zeroes_state` that mints a key, drains, and
  proves the row is gone.
- `docs/admin.md` documents the test-only endpoint, the env-var gate, and
  why the file never ships.
- `CLAUDE.md` release-tarball step now `tar --exclude='admin/_test-drain.php'`
  so the file is mechanically excluded from any future release.
