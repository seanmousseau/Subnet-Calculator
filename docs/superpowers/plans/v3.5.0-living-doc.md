## TL;DR for handover

v3.5.0 is the **third** of four IPv6-themed minor releases. It bundles
the prefix-planning items originally roadmapped for v3.4.0 (dropped
when v3.4.0 became polish/parity) with the originally-planned v3.5.0
transition theme. **No new top-level tabs.** No new design tokens. GMP
throughout for IPv6 arithmetic.

Sequencing intent: scaffold (T1), embedded-v4 detector first as the
front door (T2), transition cluster (T3–T7) tightly coupled by shared
v4 embedding/extraction primitives, prefix-planning cluster (T8–T10)
self-contained and independent, a11y + bulk batched (T11), release cut
(T12). The plan locks each PR to its own branch off `release/v3.5.0`;
only the release-cut PR (T12) merges `release/v3.5.0` into `main`.

**No deferrals without explicit user approval.** Every Acceptance
checkbox in each issue/task must have a corresponding code change AND
a test before its PR opens.

## Cross-cutting design decisions (locked)

1. **Drawer-only UI.** All 9 new tools land as `data-tool="..."` drawer
   entries on the existing IPv6 tab. NAT64 extends the existing
   `mapped6` drawer (v3.4.0).
2. **No new top-level tabs.**
3. **No new design tokens.** Consume existing `--color-*` only.
4. **GMP throughout** for IPv6 arithmetic — never PHP signed int math
   on addresses or counts. Counts that overflow signed 64-bit print as
   the `"2^N"` string form already used by `calculate_subnet6()`.
5. **Shareable URL via `sc_run_*` helpers** — same pattern as v2.11,
   v3.3.0, and v3.4.0 T5. Each new tool gets its own
   `sc_run_<tool>()` for POST+GET symmetry.
6. **`help_bubble()` on every input.** Inherited a11y from v2.5.0.
7. **Per-tool URL routes** — already locked from v3.4.0 T7. Each new
   drawer registers its name in the lookup map; the legacy
   `?tab=&tool=` query form continues to be accepted indefinitely.
8. **Embedded-v4 detector deep-links to per-scheme drawers.** As each
   per-scheme PR (T3–T7) lands, the detector's `'detail_route'` for
   that scheme moves from `null` to the per-scheme route in the same
   PR.
9. **Existing `mapped6` (v3.4.0) behaviour unchanged.** T7's NAT64
   extensions are mode-toggled additions; existing PHPUnit + Playwright
   tests for `mapped6` must keep passing unchanged.
