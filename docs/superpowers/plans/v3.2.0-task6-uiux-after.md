## Per-concern verdicts

| # | Concern | Verdict | Notes |
|---|---|---|---|
| 1 | No inline QR rendering — manual secret + `otpauth://` URI in `<details>` only | **SHIP** | The Subnet-Calculator page already shipped without QR in v3.0.0 with no operator complaints. Modern authenticators (Google Authenticator, 1Password, Authy, Bitwarden, KeePassXC) all accept manual base32 entry; most also accept pasted `otpauth://` URIs. Vendoring `chillerlan/php-qrcode` for cosmetic parity expands the dependency surface and the CI pipeline (composer dev → composer prod) for a feature operators are actively using already. Acceptable tradeoff; document in CHANGELOG. |
| 2 | Disable sub-card placement below Recovery codes | **SHIP** | Matches the project pattern of putting destructive actions at the bottom of a page (`/admin/keys.php` revoke is also at the bottom of the per-row action cluster). `Confirmation Dialogs` (severity High) is satisfied by the `onsubmit="return confirm(...)"` plus the second-factor input gate. Visual subordination via scroll order is the right ergonomic. |
| 3 | Two confirm dialogs (regenerate + disable) | **SHIP with note** | `Confirmation Dialogs` rule supports a confirm before any destructive/irreversible action. Regenerate and Disable are distinct destructive actions; an operator who triggers both should confirm both. The "naggy" risk is real but the alternative (skip confirm on Disable) violates the rule. The single `<form>` submission flow (no async pending state) makes the double-confirm fast — confirm fires before the network request, not after. Future polish: replace `confirm()` with an inline confirmation banner that requires re-typing "DISABLE" — out of scope for #347. |
| 4 | Per-code list shows row id + status, not plaintext | **SHIP** (intentional divergence from issue mock) | The issue body's mock (`KLR6-EUCA · used …`) would require either storing plaintext (security regression) OR displaying the bcrypt hash (zero forensic value, leaks hash to the page). Implementation gives the operator what's actually useful: "did someone use a recovery code? when? from where?" — answerable from row id + `used_at` + `used_via_ip`. Document the intentional divergence in the PR body so reviewers don't flag it as a missed requirement. |
| 5 | Cached enrol secret in `$_SESSION['totp_enrol_secret']` | **SHIP with cleanup recommendation** | Necessary for the verify form to round-trip the same secret the user added to their authenticator. Session is `HttpOnly + Secure + SameSite=Strict` (set by the page's session_set_cookie_params block), so the secret cannot be exfiltrated via XSS or cross-site reads. **Recommendation:** also clear `$_SESSION['totp_enrol_secret']` and `$_SESSION['totp_enrol_started']` on `totp.disable` so a subsequent enrol gets a fresh secret instead of resurrecting a stale one. Apply inline. |
| 6 | Regex-based config file rewriter | **SHIP with maintainer note** | The constraint ("single-line `$key = …;` lines only") is enforced naturally by the wizard's writers — every existing line and every new line we emit is single-line. The risk is a future maintainer who adds a `$key = [\n  'a',\n  'b',\n];` style array and breaks the rewriter. **Recommendation:** add a one-line comment to `admin_config_admin_set_keys` warning that values must be single-line `var_export` output. Apply inline. |

## Net-new issues spotted in the diff

### Must-fix

_None._

### Recommended (apply during implementation)

1. **Clear cached enrol session keys on disable.** `admin/totp.php` disable success path should `unset($_SESSION['totp_enrol_secret'], $_SESSION['totp_enrol_started']);`. Otherwise the next enrol attempt resurrects a stale secret.
2. **Add maintainer warning comment** to `admin_config_admin_set_keys` in `functions-admin-wizard.php`: "Values must be single-line `var_export` output. Multi-line array literals will not match the regex and will be appended instead of replaced."

### Nice-to-have (deferred, non-blocking)

1. **Inline QR rendering.** Vendor `chillerlan/php-qrcode` and render an inline SVG. Operator ergonomics would improve marginally for users on QR-capable apps. Out of scope for #347.
2. **Replace `confirm()` with a styled in-page banner.** More accessible (screen-reader-friendly) than the native dialog. Project hasn't done this anywhere else; rolling it out for one page would create inconsistency.
3. **Recovery code "rotate before expire" reminder.** Show a banner if the most-recent code's `created_at` is > 1 year old. Out of scope.
4. **Audit `totp.enrol.cancel`.** When operator navigates away from the enrol flow, log it. Currently only `totp.enrol.start` and `totp.enrol.verify.{ok,fail}` are audited. Low signal, minor noise.
