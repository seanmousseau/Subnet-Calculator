### Nice-to-have (deferred, non-blocking)

1. **`aria-live="polite"` on the audit `<tbody>`.** When the user clicks a filter tab, the page reloads and rows change. Screen readers will pick up the new content via the navigation event, so announcement isn't strictly required — `Aria Live` (Medium) is mostly relevant for SPA-style updates that don't trigger navigation. Re-evaluate if the filter ever becomes client-side.
2. **Arrow-key navigation between tabs (WAI-ARIA Authoring Practices).** Out of scope per project parity rule (calculator tabs also lack this). Adopt for both tab strips together in a future PR.
3. **`tabindex="-1"` on the active tab and Enter/Space activation.** The current implementation is technically `tabindex="0"` on the active tab — fine for Tab navigation. If we add arrow-key roving, swap to `tabindex="-1"` everywhere except the focused tab.
4. **Highlight current page tab on light theme.** The `.tab-btn.active` rule uses `color: var(--color-accent-light)`. Verified in dark mode but should be eyeballed in light mode (existing tab strip already shipped in light mode for v2.9.0, so this is "trust the precedent" rather than a new risk).
5. **Caption visibility on screen reader.** `<caption class="sr-only">` is correctly inside the `<table>` and announced by NVDA/VoiceOver. No change needed.
