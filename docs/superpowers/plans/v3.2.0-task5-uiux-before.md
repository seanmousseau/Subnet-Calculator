## Findings classified

### Must-fix (blocks merge)

_None._

### Recommended (apply during implementation)

1. **Sticky thead `z-index: 2`** (not `1`) — sit above striped rows and any inline overlays the badge classes might add, but stay well under the 1000 floor for fixed-position chrome.
2. **Pagination padding parity** — wrap `<a>` and `<span>` in a shared class (e.g. `.admin-pager-item`) so the disabled side doesn't collapse narrower than the active side.
3. **Unit test the precedence edge case** — `auth.login.fail` → `badge-multicast` (suffix beats prefix). Without this assertion the precedence is implicit and easy to flip.

### Nice-to-have (defer; non-blocking)

1. **Tablist arrow-key navigation.** Per WAI-ARIA Authoring Practices, tablist tabs should support `←`/`→` to move between tabs without losing focus. The Subnet-Calculator's calculator tabs use plain `Tab` navigation (DOM-order) — staying consistent with that means the audit tablist also doesn't need arrow keys. If we add arrow-key support to the audit tablist later, do the same upgrade for the calculator tabs in one PR.
2. **`role="tab"` paired with `role="tabpanel"`.** The audit log isn't actually a tabpanel pattern — the "tabs" filter the same single table. The issue body explicitly asks for `role="tablist"`/`role="tab"` styling, but a stricter interpretation would use `role="radiogroup"` + `role="radio"` since the filters mutate the page query (they don't swap visible regions). Going with the issue's request (tablist) for consistency with the calculator.
