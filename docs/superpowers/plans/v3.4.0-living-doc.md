## TL;DR for handover

v3.4.0 is the **second** of four IPv6-themed minor releases. It bundles
6 carry-forward cleanups, 4 internal-architecture items, and 2 new tools
(`rdns6`, `mapped6`) as **drawer entries on the existing IPv6 tab**. **No
new top-level tabs.** No new design tokens. GMP throughout for IPv6
arithmetic.

Sequencing intent: cleanups + helper extraction first (T2–T3), then the
larger internal refactors (T4–T7), then the two new tools (T8–T9), then
parity/a11y (T10–T11), then release cut (T12). The plan locks each PR to
its own branch off `release/v3.4.0`; only the release-cut PR (T12) merges
`release/v3.4.0` into `main`.

**No deferrals without explicit user approval.** Every Acceptance checkbox
in each issue/task must have a corresponding code change AND a test before
its PR opens.

## Cross-cutting design decisions (locked)

1. **Drawer-only UI.** New tools (`rdns6`, `mapped6`) land as
   `data-tool="..."` drawer entries on the existing IPv6 tab.
2. **No new top-level tabs.**
3. **No new design tokens.** Consume existing `--color-*` only.
4. **GMP throughout** for IPv6 arithmetic — never PHP signed int math on
   addresses or counts. Counts that overflow signed 64-bit print as the
   `"2^N"` string form already used by `calculate_subnet6()`.
5. **Shareable URL via `sc_run_*` helpers** — same pattern as v2.11 and
   v3.3.0. T5 refactors flat globals into per-tool arrays without
   breaking the POST+GET symmetry.
6. **`help_bubble()` on every input.** Inherited a11y from v2.5.0.
7. **Back-compat on URL routes (T7).** New `/ipv6/<tool>` routes coexist
   with the existing `?tab=&tool=` query-string scheme — old shareable
   URLs must continue to resolve.
