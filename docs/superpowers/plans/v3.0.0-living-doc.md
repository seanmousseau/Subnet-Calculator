## Cross-cutting design decisions (locked)

1. **Session schema is bumped once** in PR1 (#315) to a versioned v2 with a
   `type` discriminator. `'ipv4' | 'ipv6'` ship in PR1, `'tree'` is added by
   PR3 (#302). The schema file allows all three from PR1 to avoid a second
   bump mid-release — server validation for `'tree'` activates in PR3 but the
   schema is already permissive.
2. **Admin config file is split.** `config-admin.php` is the wizard target and
   may be auto-written. `config.php` remains hand-edited only. PR2 introduces
   the split; PR1 should already include `config-admin.php` to the
   `require_once` chain in `index.php` so the wizard has somewhere to write.
3. **Audit log is the cross-feature breadcrumb.** First-run wizard, TOTP, key
   mint/revoke all write into the same `admin_audit` table from PR1. PR2
   features just call `admin_audit_log($action, $meta)`.
4. **No new runtime dependencies.** TOTP is hand-rolled. Tree editor is plain
   JS (no React/Vue). Keep the `vendor/xlsx/` SRI pattern as the only
   third-party JS.
5. **Mobile-aware but desktop-first** for new UI. Tree editor explicitly
   degrades to action sheets on touch (per design lock §"Mobile interaction
   model"). Keyboard overlay is desktop-only (touch users can't trigger `?`).

New gaps surfaced:
- **bcrypt hashes are semgrep-blocked** in committed source (CWE-798). The Docker test rig generates the hash at build time inside a `RUN` step instead. Worth documenting somewhere if other contributors want a local test config — they need to run `php -r "echo password_hash(...)"` themselves.
- **The lazy `audit_purge()` runs inside every `audit_log()` call.** Fine at low volume, but a busy admin (e.g. mass key rotation) could pay an extra DELETE per write. If audit volume becomes substantive in v3.x, consider a cron-style sampled purge. Not actioned now.

- **`session_save_tab` is derived from `$active_tab`, not from the saved payload.** Correct because save always happens on the same tab the form is on, but a future refactor that allows cross-tab save would need to revisit.
