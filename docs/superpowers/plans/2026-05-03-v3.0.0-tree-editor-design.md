# v3.0.0 — Interactive Subnet Tree Editor (#302) — Locked Design

**Date:** 2026-05-03
**Issue:** [#302](https://github.com/seanmousseau/Subnet-Calculator/issues/302)
**Status:** Design locked, implementation pending (PR3)

The brainstorm in the v3.0.0 kickoff session locked these decisions. PR3 must
implement against this doc — any deviation requires a new brainstorm.

## State model

**Client-only JS state with localStorage autosave + manual session save.**

- All edits live in a JS reducer-style state. No server round-trip per edit.
- Autosave to `localStorage` under key `sc.tree.draft.<rootCidr>` after every
  mutation (debounced 300 ms). Reload restores from localStorage if present.
- Explicit "Save Session" button persists via the new `type: 'tree'` session
  payload (see §"Session schema" below) — this is the cross-device path.
- Rationale: keeps the server stateless for edits, removes conflict-handling
  burden, ties cleanly into #315's schema bump and #301's history pane.

## Edit operations (all in v3.0.0)

| Operation | Trigger | Notes |
|---|---|---|
| **Click-split** | Click node → picker modal `2 / 4 / 8 / 16` children | Server-validated against the prefix length floor (/30 IPv4, /126 IPv6 — but the editor allows down to /32 / /128 for documentation purposes). |
| **Drag-merge** | Drag a node onto its sibling (desktop) | Merges both back into the parent. Only sibling-merge — no arbitrary merges. |
| **Merge action** | Tap node → action sheet → "Merge with sibling" (mobile) | Replaces drag for touch. |
| **Rename + notes** | Click pencil icon on node → inline editor with `name` + `notes` textarea | Persisted in tree-type session payload, omitted from copy-as-CIDR. |
| **Undo / Redo** | Toolbar buttons + `Ctrl/Cmd+Z` / `Ctrl/Cmd+Shift+Z` | Stack capped at 50 entries. |

## Mobile interaction model

**Desktop-first; touch uses tap → action sheet** (option 1 in brainstorm).

- `@media (hover: none)` swaps the click-handler to open a bottom sheet
  containing: Split, Merge with sibling, Rename, Delete (cancel).
- No drag-merge on touch (Playwright flake risk + UX awkward on small screens).
- All operations remain available via the action sheet — no feature gap.

## Export

All four formats ship in v3.0.0 (full multi-select from brainstorm):

1. **Save as Session** — POSTs the tree as a `type: 'tree'` payload (see §schema).
   Lossless round-trip; restores names + notes + structure.
2. **Copy as CIDR list / Markdown / Cisco** — three buttons matching the
   existing pattern from `functions-vlsm.php` exports. Lossy (drops names/notes
   in CIDR; preserves names in Markdown/Cisco as comments).
3. **Download CSV (lossy) / JSON (lossless)** — matches `vlsm-csv-export` /
   `vlsm-json-export` plumbing in `app.js`.
4. **Shareable URL** — base64url-encoded JSON of the tree state in `?tree=…`.
   Soft-cap of 50 nodes (~3 KB after b64 → ~4 KB query-string headroom on
   most servers). Above the cap, the share button shows "Tree too large to
   share — save as session and share that URL instead."

## Session schema (`type: 'tree'`) — DEPENDS ON #315 SCHEMA BUMP

`vlsm-session.schema.json` v2 (from #315) must include `tree` as a value of
the `type` discriminator. Shape:

```json
{
  "type": "tree",
  "root": {
    "cidr": "10.0.0.0/16",
    "name": "Corp HQ",
    "notes": "WAN edge → distribution",
    "children": [
      {
        "cidr": "10.0.0.0/17",
        "name": "Production",
        "children": [
          { "cidr": "10.0.0.0/18", "name": "DC East" },
          { "cidr": "10.0.64.0/18", "name": "DC West" }
        ]
      },
      { "cidr": "10.0.128.0/17", "name": "Lab" }
    ]
  }
}
```

Validation rules (server-side, on POST):

- Each `children` array, if present, must have ≥2 entries.
- Each child's network must fall inside the parent and be aligned to its prefix.
- Children must be non-overlapping but **may have gaps** (intentional reserves).
- `name` ≤ 128 chars; `notes` ≤ 1024 chars; both optional.
- Tree depth ≤ 16 (defensive cap; deepest legal IPv4 chain is 32 levels).
- Total node count ≤ 1024.

## Server endpoints

No new endpoints. The tree editor reuses:

- `POST /api/v1/sessions` — accepts the new `type: 'tree'` payload
  (validated against `vlsm-session.schema.json` v2).
- `GET /api/v1/sessions/{id}` — returns the same payload.
- `GET /api/v1/tree?cidr=…` — existing read-only tree endpoint, used to seed
  a fresh editor session from a CIDR with no prior tree.

## Acceptance criteria for #302

1. From `/tree?cidr=10.0.0.0/24`, user can split the root into 4 children, rename
   each, then download as JSON. The JSON validates against
   `vlsm-session.schema.json` v2.
2. Save Session round-trip: edit → save → reload from `/sessions/{id}` →
   identical tree state.
3. `Ctrl+Z` reverts the last edit; the autosaved localStorage entry updates.
4. Reload after edits with no save → editor restores from localStorage.
5. On a touch device (Playwright `is_mobile=true`), tap a node opens the action
   sheet; drag is disabled.
6. PHPStan L9 clean, PHPCS PSR-12 clean, ESLint clean, Stylelint clean,
   Spectral lint clean, Playwright suite green (full prior suite + new tree
   groups), Semgrep clean.
