## TL;DR for handover

v3.6.0 is the **fourth and final** of four IPv6-themed minor releases.
Four multicast tools — scope decoder (front door), SSM
(unicast-prefix-based), embedded-RP, PMTU helper — all on the existing
IPv6 tab as drawer entries. **No new top-level tabs.** No new design
tokens. GMP throughout for IPv6 arithmetic.

Sequencing intent: scaffold (T1), scope decoder first as front door
(T2, also migrates `ipv6_in_prefix()` to `functions-ipv6.php`), SSM
before embedded-RP (T3 → T4) since RP layers on SSM's bit shape, PMTU
last in feature cluster (T5, fully independent), a11y + bulk batched
including v3.5.0 a11y test strengthening (T6), release cut (T7).

**No deferrals without explicit user approval.**

## Cross-cutting design decisions (locked)

1. **Drawer-only UI.** All 4 new tools land as `data-tool="..."` drawer
   entries on the existing IPv6 tab.
2. **No new top-level tabs.** No new design tokens. Reuse existing
   `--color-*` only.
3. **GMP throughout** for IPv6 arithmetic — never PHP signed-int math.
4. **Shareable URL via `sc_run_*` helpers** — same pattern as
   v2.11/v3.3.x/v3.4.x/v3.5.x.
5. **`help_bubble()` on every input.** Inherited a11y from v2.5.0.
6. **Per-tool URL routes** — already locked from v3.4.0 T7. Each new
   drawer registers its name in the lookup map.
7. **Multicast scope decoder is the front door.** T2 lands first; T3/T4
   per-scheme decoders deep-link back via `detail_route`. PMTU (T5) is
   independent.
8. **`ipv6_in_prefix()` migration in T2.** Helper moves from
   `functions-embedded-v4.php` to `functions-ipv6.php` so multicast
   detection (and any future tool) can reuse it. Pure file move; no
   behaviour change.
9. **Production deploys MUST use anchored rsync excludes**
   (`--exclude='/config.php' --exclude='/data/'`) per v3.5.0
   deploy-runbook fix. Locked into T7 release-cut steps.
