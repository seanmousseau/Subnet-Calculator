## Task 2: Embedded-v4 detector (front door) — issue #390

**Branch:** `feature/v3.5.0-embedded-v4` off `release/v3.5.0`.

**Files:** per the new-tool template above. The module name is `functions-embedded-v4.php`; handler `embedded-v4.php`; drawer `data-tool="embedded-v4"`; endpoint `POST /api/v1/embedded-v4`; doc `docs/embedded-v4.md`.

### Why this is first

The detector is the "what is this address?" front door for the rest of v3.5.0. It must land before the per-scheme drawers so each per-scheme PR (T3–T7) immediately wires its detection logic back into the unified entry point. The detector's per-scheme detection helpers will be **stubbed** in this task (return null/false) and replaced with real implementations as their per-scheme PRs land. T11's a11y audit verifies the deep-link UX is solid once all per-scheme drawers exist.

### Function signatures

```php
// Subnet-Calculator/includes/functions-embedded-v4.php
declare(strict_types=1);

/**
 * Detect any embedded-IPv4 scheme in the given IPv6 address.
 *
 * Returns an array of shape:
 *   [
 *     'scheme'      => 'mapped'|'compatible'|'6to4'|'teredo'|'nat64-wkp'|'nat64-nsp'|'isatap'|null,
 *     'ipv4'        => string|null,           // dotted-quad
 *     'deprecated'  => bool,                  // true for ::ffff:0:0/96 vs ::/96
 *     'detail_route'=> string|null,           // /ipv6/<tool> URL for deep-link
 *     'extra'       => array<string, mixed>,  // scheme-specific (e.g. teredo flags, 6to4 surrounding bits)
 *   ]
 *
 * Returns ['scheme' => null, 'ipv4' => null, ...] when no embedded v4 is detected.
 */
function detect_embedded_v4(string $ipv6): array;

/**
 * Helper: is the address inside a given /N prefix? Uses GMP throughout.
 */
function ipv6_in_prefix(string $address, string $prefix, int $prefix_length): bool;
```

### Failing tests (T2 step 2)

}

}

public function test_no_embedding_returns_null(): void

### Implementation outline (T2 step 4)

`detect_embedded_v4()` checks each scheme in priority order — mapped → compatible → 6to4 → teredo → nat64-wkp → isatap. Mapped/compatible/6to4 all have fixed prefixes; nat64-wkp is `64:ff9b::/96`; teredo is `2001:0::/32`; isatap matches the `*0000:5efe:V4ADDR` or `*0200:5efe:V4ADDR` IID pattern. Each branch extracts the embedded IPv4 via `inet_pton()` byte indexing — never via signed-int arithmetic.

For the per-scheme detail-route deep-links, use `/ipv6/embedded-v4` for the detector itself; the per-scheme drawers don't exist yet (they land T3–T7), so seed the deep-links as `null` in T2 and update them as the per-scheme PRs merge.

## Task 3: 6to4 address tool (RFC 3056) — issue #392

**Branch:** `feature/v3.5.0-6to4` off `release/v3.5.0`.

**Files:** template defaults; module `functions-6to4.php`; handler `6to4.php`; drawer `data-tool="6to4"`; endpoint `POST /api/v1/6to4`; doc `docs/6to4.md`.

### Function signatures

```php
declare(strict_types=1);

/**
 * Convert a public IPv4 address to its 6to4 prefix.
 * Returns the 2002:WWXX:YYZZ::/48 prefix as a string.
 * Throws InvalidArgumentException on private/reserved/multicast IPv4.
 */
function ipv4_to_6to4(string $public_ipv4): string;

/**
 * Decode a 6to4 IPv6 address back to its embedded public IPv4.
 * Returns ['ipv4' => '...', 'subnet_id' => int, 'interface_id' => string].
 * Throws InvalidArgumentException if the address is not under 2002::/16.
 */
function decode_6to4(string $ipv6): array;
```

### Test vectors (RFC 3056 §2)

```php
// 192.0.2.1 → 2002:c000:0201::/48
public function test_ipv4_to_6to4_basic(): void
{
    $this->assertSame('2002:c000:0201::/48', ipv4_to_6to4('192.0.2.1'));
}

public function test_decode_6to4_basic(): void
{
    $r = decode_6to4('2002:c000:0201::1');
    $this->assertSame('192.0.2.1', $r['ipv4']);
}

public function test_private_ipv4_rejected(): void
{
    $this->expectException(InvalidArgumentException::class);
    ipv4_to_6to4('10.0.0.1');
}

public function test_multicast_ipv4_rejected(): void
{
    $this->expectException(InvalidArgumentException::class);
    ipv4_to_6to4('239.0.0.1');
}

public function test_decode_rejects_non_2002(): void
{
    $this->expectException(InvalidArgumentException::class);
    decode_6to4('2001:db8::1');
}
```

### Implementation outline

- `ipv4_to_6to4`: validate via `filter_var` + `FILTER_FLAG_NO_PRIV_RANGE | FILTER_FLAG_NO_RES_RANGE`, also reject multicast `224.0.0.0/4`. Pack the 4 bytes into the second/third hexadectets of `2002::`.
- `decode_6to4`: verify under `2002::/16`, extract bytes 2–5 as the embedded IPv4, bytes 6–7 as the subnet-ID, bytes 8–15 as the interface-ID.

## Task 4: Teredo address decoder (RFC 4380) — issue #393

**Branch:** `feature/v3.5.0-teredo` off `release/v3.5.0`.

**Files:** template defaults; module `functions-teredo.php`; handler `teredo.php`; drawer `data-tool="teredo"`; endpoint `POST /api/v1/teredo`; doc `docs/teredo.md`.

### Function signatures

```php
declare(strict_types=1);

/**
 * Decode a Teredo IPv6 address per RFC 4380.
 * Returns:
 *   [
 *     'server_ipv4' => string,    // bits 32–63 (raw)
 *     'flags'       => int,       // bits 64–79
 *     'cone'        => bool,      // flags & 0x8000
 *     'port'        => int,       // bits 80–95 XOR 0xFFFF
 *     'client_ipv4' => string,    // bits 96–127 XOR 0xFFFFFFFF
 *   ]
 * Throws InvalidArgumentException if the address is not 2001:0::/32.
 */
function decode_teredo(string $ipv6): array;

/**
 * Encode a Teredo address from its parts.
 */
function encode_teredo(string $server_ipv4, string $client_ipv4, int $port, int $flags = 0x8000): string;
```

### Test vectors (RFC 4380 §4 example)

```php
// RFC 4380 example:
//   server = 65.54.227.120
//   client = 192.0.2.45 (post-XOR)
//   port   = 40000      (post-XOR)
//   flags  = 0x8000 (cone)
// Encoded address: 2001:0:4136:e378:8000:63bf:3fff:fdd2
public function test_decode_rfc4380_example(): void
{
    $r = decode_teredo('2001:0:4136:e378:8000:63bf:3fff:fdd2');
    $this->assertSame('65.54.227.120', $r['server_ipv4']);
    $this->assertSame(40000, $r['port']);
    $this->assertSame('192.0.2.45', $r['client_ipv4']);
    $this->assertTrue($r['cone']);
}

public function test_encode_round_trip(): void
{
    $addr = encode_teredo('65.54.227.120', '192.0.2.45', 40000, 0x8000);
    $this->assertSame('2001:0:4136:e378:8000:63bf:3fff:fdd2', $addr);
}

public function test_decode_rejects_non_teredo(): void
{
    $this->expectException(InvalidArgumentException::class);
    decode_teredo('2001:db8::1');
}
```

### Implementation outline

- `decode_teredo`: validate prefix `2001:0::/32` (bytes 0–3 = `20 01 00 00`), extract server IPv4 from bytes 4–7, flags from bytes 8–9, XOR port (bytes 10–11 with `0xFFFF`), XOR client IPv4 (bytes 12–15 with `0xFFFFFFFF`).
- `encode_teredo`: pack inputs into 16 bytes with the inverse XORs.

```markdown
## [3.5.0] - 2026-MM-DD

**IPv6 Prefix Planning + Transition.** Combines the prefix-planning items
originally roadmapped for v3.4.0 (dropped when v3.4.0 became polish/parity)
with the originally-planned v3.5.0 transition theme. Nine new IPv6-tab
drawer entries with REST endpoints, shareable URLs, Playwright coverage,
and a11y assertions across all 9 drawers.

### Added

- **IPv6 embedded-v4 detector.** Front-door tool: detects IPv4-mapped,
  IPv4-compatible (deprecated), 6to4, Teredo, NAT64 well-known, and
  ISATAP embeddings; extracts the embedded IPv4. Deep-links to per-scheme
  tools. (#390)
- **6to4 address tool (RFC 3056).** Bidirectional translation between
  public IPv4 and `2002::/16` 6to4 prefixes. (#392)
- **Teredo address decoder (RFC 4380).** Decode and encode `2001:0::/32`
  Teredo addresses. (#393)
- **ISATAP interface-ID helper (RFC 5214).** Build and decode ISATAP IIDs
  for both globally-unique and non-globally-unique IPv4. (#394)
- **6rd address tool (RFC 5969).** Service-provider 6to4 variant with
  configurable SP IPv6 prefix and IPv4 mask length. (#395)
- **NAT64 / DNS64 helper (RFC 6052/6146/6147).** Extends the v3.4.0
  `mapped6` drawer with all six RFC 6052 prefix lengths, custom prefix
  support, and DNS64 AAAA synthesis. (#391)
- **IPv6 prefix-delegation planner.** Slice a delegated prefix (e.g. /48)
  into nibble-aligned children with a usage table. (#387)
- **IPv6 nibble-boundary helper.** Show nibble-aligned neighbours for any
  IPv6 prefix. (#388)
- **RFC 3531 sparse-allocation guidance.** Bit-reservation strategy tool
  (Centermost / Leftmost / Rightmost). (#389)
- **Bulk endpoint coverage for v3.5.0 endpoints.** `items[]` mode now
  accepts the 9 new operations.
- **Playwright a11y assertions for the 9 new IPv6 drawers.**

### Changed

- **`mapped6` drawer extended** with NAT64 prefix-length modes (existing
  IPv4-mapped behaviour unchanged).
```
