## Issue #298 — Rate-limit headers

**Reality check:** The issue says "document the existing X-RateLimit-* headers." A grep confirms they do not exist — only `Retry-After` is sent on 429. So this is code + docs, not docs-only.

**Headers to emit on every response (success or error) when rate limiting is active:**

- `X-RateLimit-Limit:` — RPM ceiling for this client
- `X-RateLimit-Remaining:` — requests left in the current 60-second window
- `X-RateLimit-Reset:` — unix epoch seconds when the window rolls over
- `Retry-After:` — only on 429, seconds until reset (already implemented)

**Implementation:** `api_rate_limit()` in `helpers.php` already counts hits in SQLite. Emit the three new headers immediately after the count check, before the insert. When `$rpm <= 0` (rate limiting disabled), emit nothing.

**OpenAPI:** Add reusable header components and reference them on every response in every operation. Spectral lint must stay clean.

## Issue #299 — VLSM session JSON-Schema

**Existing payload shape** (from `request.php`):

```json
{
  "network": "10.0.0.0",
  "cidr": "24",
  "requirements": [
    {"name": "LAN", "hosts": 50}
  ]
}
```

**Plan:**
1. Create `Subnet-Calculator/api/schemas/vlsm-session.schema.json` (Draft 2020-12). Only the IPv4 shape that actually round-trips today; do not over-spec IPv6 fields that don't exist yet.
2. Add `GET /api/v1/schemas/vlsm-session` endpoint that serves the schema with `Content-Type: application/schema+json`.
3. Reference the schema URL from openapi.yaml `/sessions` POST request body and GET response body.
4. Doc page `docs/schemas.md` with example validation.
5. PHPUnit test asserting schema validity (parse it as JSON, confirm `$schema` and `$id`).
6. Playwright test: GET endpoint returns 200 and matches the file content.

## Issue #297 — API key admin UI

**Storage:** Reuse `data/sessions.sqlite` when `$session_enabled = true`, else create `data/admin.sqlite`. New table:

```sql
CREATE TABLE api_keys (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  name          TEXT    NOT NULL,
  prefix        TEXT    NOT NULL,           -- first 8 chars of the public token, for UI listing
  token_hash    TEXT    NOT NULL UNIQUE,    -- bcrypt hash of full token
  created_at    INTEGER NOT NULL,
  last_used_at  INTEGER,                    -- updated by api_authenticate() on use
  revoked_at    INTEGER                     -- NULL = active
);
CREATE INDEX idx_api_keys_prefix ON api_keys(prefix);
```

**Token format:** `sk_live_` + 32 hex chars (16 random bytes). Public prefix = first 8 chars after `sk_live_` for UI display ("sk_live_a1b2c3d4…").

**Auth bootstrap:**
- New config: `$admin_ui_enabled = false`, `$admin_user = ''`, `$admin_pass_hash = ''` (PASSWORD_BCRYPT). Operator generates the hash with `php -r "echo password_hash('mypass', PASSWORD_BCRYPT);"`.
- Admin page checks both — empty hash + UI enabled = config error page.
- Login uses HTTP Basic. Compare with `password_verify`. Constant-time. No session — re-auth every request.
- Failed logins are rate-limited the same way as the API.

**Files:**

- `Subnet-Calculator/includes/functions-apikeys.php` — `apikey_create`, `apikey_list`, `apikey_revoke`, `apikey_verify`, `apikey_record_use`
- `Subnet-Calculator/includes/functions-admin-auth.php` — `admin_authenticate()` middleware
- `Subnet-Calculator/admin/index.php` — bootstrap, requires admin auth
- `Subnet-Calculator/admin/keys.php` — list/create/revoke UI
- `Subnet-Calculator/admin/.htaccess` — block direct includes; require Basic Auth realm
- `Subnet-Calculator/api/v1/handlers/admin_keys.php` — JSON CRUD for the same data
- `Subnet-Calculator/testing/unit/ApiKeysTest.php` — TDD coverage

**`api_authenticate()` extension:** After the existing in-memory `$api_tokens` check fails (or if `$api_tokens === []`), check the SQLite `api_keys` table. Both can coexist.

**OpenAPI:** Add `/admin/keys` POST/GET, `/admin/keys/{id}` DELETE under a new `Admin` tag, gated by `securitySchemes.basicAuth`.

## Risk register

- **Bcrypt cost** — default 10 rounds. Each admin auth check ~100ms. Acceptable.
- **Concurrent token rotation** — UNIQUE constraint on `token_hash` prevents collisions; bcrypt collision probability is negligible.
- **Admin UI XSS** — must use `htmlspecialchars` everywhere. No JS framework, plain server-rendered HTML.
- **Token leakage in logs** — never log the raw token. Only the prefix.

## Out of scope (deferred to v3.0.0)

- Setup wizard for first-run admin password
- Per-key rate-limit overrides via UI (still possible via `$api_rate_limit_tokens`)
- Audit log of admin actions
- TOTP / 2FA on admin
