# v3.4.0 Design — IPv6 Polish, Architecture, Parity

**Status:** Approved 2026-05-08
**Predecessor:** v3.3.0 (IPv6 Foundations, shipped 2026-05-07, tag `v3.3.0` @ `049f95d`)
**Plan:** `docs/superpowers/plans/2026-05-08-v3.4.0-release.md` (to be written from this spec)

---

## Goal

Close out v3.3.0's technical-debt carry-forwards, harden the new IPv6 surface (a11y, bulk endpoint coverage, address-type detection breakout), introduce per-tool URL routes (`/ipv6/derive`-style) without breaking existing `?tab=&tool=` query-param URLs, and ship two parity tools — IPv6 reverse-DNS (rdns6) and IPv4-mapped/translated IPv6 (`::ffff:0:0/96` + NAT64 `64:ff9b::/96`).

Twelve PRs total. No new top-level tabs. All new tools land as drawer entries on the existing IPv6 tab. Same release shape as v3.3.0 (sequential PRs into `release/v3.4.0`, final cut PR opens `release/v3.4.0 → main`).

---

## Architecture

PHP 8.2+ application as it stands today (slim `index.php` bootstrap → `includes/config.php` → `includes/functions-*.php` pure helpers → `includes/request.php` controller → `templates/layout.php` render). v3.4.0 introduces:

- **Per-tool URL routing** layered on top of existing `?tab=&tool=` query params. New canonical form `/ipv4/<tool>` and `/ipv6/<tool>`, with rewrite back-compat from the legacy form so iframe consumers and shared bookmarks keep working.
- **Per-tool template variable arrays** replacing the ~16 flat `$tool_*` global blocks in `request.php` — each tool exports a single `$<tool>` array keyed by its result fields. Template echo sites are mechanically updated.
- **Three new modules** carved from existing files:
  - `functions-zone6.php` ← `parse_zone_id` from `functions-derive6.php`
  - `functions-slaac6.php` ← `slaac_privacy_address` from `functions-derive6.php`
  - `functions-type6.php` ← IPv6 type detection (`get_ipv6_type` and friends) from `functions-util.php`
- **Two new modules** for new tools:
  - `functions-rdns6.php` (parity with existing v4 reverse-DNS, GMP-driven nibble expansion to `ip6.arpa`)
  - `functions-mapped6.php` (IPv4-mapped `::ffff:0:0/96` + NAT64 `64:ff9b::/96` bidirectional convert + detection)
- **One new shared template helper:** `copy_button($value, $label)` in `functions-util.php` (alongside `help_bubble()`). Replaces 9–12 inline duplicates in `templates/layout.php`.

No new dependencies. No new design tokens. No new top-level tabs.

## Carry-forward debt items (from v3.3.0)

### #1 Split `functions-derive6.php`
**Where:** `Subnet-Calculator/includes/functions-derive6.php` (~342 lines)
**Outcome:** Three focused modules.
- `functions-zone6.php` — `parse_zone_id($input): array` (hosts the public zone-ID parser).
- `functions-derive6.php` (smaller) — `mac_to_eui64`, `link_local_from_mac`, `solicited_node_from_mac`, `mac_normalize_internal`, `derive_from_mac`.
- `functions-slaac6.php` — `slaac_privacy_address` and any private RFC 8981 helpers it currently inlines.
**Constraints:** All call sites in `request.php`, `api/v1/handlers/`, and tests are updated. Public API surface unchanged. PHPStan L9 still passes.

### #2 Extract `copy_button($value, $label)` helper
**Where:** `Subnet-Calculator/includes/functions-util.php` (alongside `help_bubble`).
**Signature:** `copy_button(string $value, string $label): string` — returns escaped HTML for a single copy button (mirrors existing inline pattern: `<button type="button" class="copy-btn" data-clipboard-text="...">`).
**Outcome:** All current inline duplicates in `templates/layout.php` (zoneid, derive, slaac, and any v4 tool drawers using the same pattern) replaced by `<?= copy_button(...) ?>`. Existing JS handler in `app.js` continues to work unchanged (selector-based).

### #3 Refactor `request.php` flat globals → per-tool arrays
**Where:** `Subnet-Calculator/includes/request.php`, `Subnet-Calculator/templates/layout.php`.
**Outcome:** Each tool's result variables collapse from N flat globals into one associative array. Example: `$zoneid_address`, `$zoneid_zone`, `$zoneid_canonical`, `$zoneid_error` → `$zoneid = ['address' => …, 'zone' => …, 'canonical' => …, 'error' => …]`. Empty-state default is `$<tool> = []`. Template echo sites read `$zoneid['address'] ?? ''` etc.
**Scope:** All ~16 tools — IPv4, IPv6, splitter, splitter6, VLSM, VLSM6, supernet, supernet6, ULA, rdns, range, range6, tree, overlap, lookup, diff, zone-id, derive, slaac-privacy.
**Test gate:** Full Playwright pass after refactor — every tool's render path changes shape.
**Out of scope:** Renaming any of the underlying field names (purely a container shape change).

### #4 Fix EUI-64 docstring typo
**Where:** `docs/superpowers/plans/2026-05-06-v3.3.0-release.md` and `docs/internal/specs/2026-05-06-v3.3.0-ipv6-foundations-design.md`. Both currently show EUI-64 = `0226:b9ff:fe7e:abcd` for MAC `00:24:b9:7e:ab:cd`. Correct value is `0224:b9ff:fe7e:abcd`. Pure doc fix.

### #5 Resolve `RangeTest` TODO
**Where:** `testing/unit/RangeTest.php`, `Subnet-Calculator/includes/functions-range.php`.
**Outcome:** `range_to_cidrs(string $start, string $end, ?int $cap = null): array` accepts the cap as an optional parameter (falls back to `$GLOBALS['range_max_cidrs']` only when `null` for back-compat with current callers in `request.php` and `api/v1/handlers/range.php`). The `setUp/tearDown` `$GLOBALS` dance in `RangeTest.php` is removed; the cap test passes the value directly.

### #6 Clarify `ul_bit_flipped` semantics
**Where:** `Subnet-Calculator/includes/functions-derive6.php` (after the split, this lives in the smaller `functions-derive6.php`) and the OpenAPI `derive` endpoint schema.
**Outcome:** Docblock and OpenAPI description clarified to read "true if the U/L bit was originally 0 in the input MAC (and was therefore flipped to 1 to form the EUI-64 modified-IID); false if it was already 1." Field name is **not** changed — renaming is a breaking API change deferred to v4.0.0. Docblock-only fix.

## Architecture items

### A. A11y audit of 5 new IPv6 drawers
**Drawers covered:** zone-id, derive, slaac-privacy, rdns6 (new), mapped6 (new).
**Checks:**
- Every input has a `<label>` (or `aria-label`) and a `help_bubble()` icon.
- All `copy_button()` outputs have visible focus rings + `aria-label="Copy <field name>"`.
- Drawer disclosure (the existing `<details>`/`<summary>` Advanced section, where present) is keyboard-operable and announces expanded state.
- Tab order: input → submit → result fields → copy buttons → next field. No focus traps.
- `prefers-reduced-motion` honoured for any new transitions.
- Colour-contrast pass for any new text against teal accent (`--color-accent`).
**Test additions:** Playwright a11y assertions extended to the two new drawers and any fixes applied to the three existing ones.

### B. Bulk endpoint expansion
**Where:** `Subnet-Calculator/api/v1/handlers/bulk.php`, `api/openapi.yaml`.
**Outcome:** The existing bulk endpoint accepts batch requests for the v3.3.0 IPv6 endpoints (`range6`, `supernet6`, `zone-id`, `derive`, `slaac-privacy`) and the two new v3.4.0 endpoints (`rdns6`, `mapped6`). Per-item errors are returned in the same envelope format as existing bulk operations.
**Tests:** PHPUnit cases for each new endpoint via bulk; Playwright case exercising the bulk endpoint over HTTP.

### C. IPv6 type-detection breakout → `functions-type6.php`
**Where:** Move `get_ipv6_type` and any v6-specific helpers currently bundled in `functions-util.php` into a new `functions-type6.php`.
**Outcome:** `functions-util.php` keeps generic helpers (`help_bubble`, `copy_button`, badge rendering); `functions-type6.php` owns IPv6 classification (loopback, ULA, link-local, multicast, GUA, IPv4-mapped, NAT64, Teredo, 6to4, documentation prefix, etc.). Public function names unchanged. `index.php` requires the new file.

### D. Per-tool URL routes
**Where:** `Subnet-Calculator/index.php`, `Subnet-Calculator/.htaccess`, `Subnet-Calculator/includes/request.php`, `Subnet-Calculator/assets/app.js`, every docs page that links a deep tool.
**Outcome:**
- New canonical URL form: `/ipv4/<tool>` and `/ipv6/<tool>` (e.g. `/ipv6/derive`, `/ipv4/vlsm`). Tabs without a tool: `/ipv4`, `/ipv6`. Root `/` keeps current behaviour (default tab from config).
- Apache `.htaccess` rewrite maps `/ipv[46]/<tool>` → `index.php?tab=ipv[46]&tool=<tool>` internally, preserving query-string for shareable parameters.
- Shareable URLs in `app.js` emit the new canonical form; the existing `?tab=&tool=` form continues to be accepted (round-trip back-compat).
- Iframe consumers using `?tab=&tool=` keep working — no breaking change.
- All docs pages updated to link the canonical form.
**Tests:** Playwright cases asserting both URL forms route to the same rendered content; legacy form is preserved (no auto-redirect that would break iframes); shareable URL output uses the new canonical form.

## New tools

### E. IPv6 reverse-DNS (rdns6)
**Module:** `Subnet-Calculator/includes/functions-rdns6.php` — `ipv6_to_arpa(string $address, ?int $prefix = null): string` (full-address `ip6.arpa` form, or zone delegation when prefix is multiple of 4).
**Drawer:** New IPv6-tab drawer "Reverse DNS (rdns6)". Inputs: address, optional prefix length. Outputs: `ip6.arpa` zone, full nibble form, copy-as-BIND-zone snippet. Mirrors the v4 `rdns` drawer's UX.
**API:** `POST /api/v1/rdns6` (and bulk coverage from item B).
**Constraints:** Prefix length must be a multiple of 4 for zone-delegation form (RFC 3596); reject non-nibble-aligned prefixes with a clear error.
**Tests:** PHPUnit (link-local, ULA, GUA, full /128, /64, /48, /4, /0, error cases); Playwright drawer test; OpenAPI Spectral pass.

### F. IPv4-mapped / translated IPv6 (mapped6)
**Module:** `Subnet-Calculator/includes/functions-mapped6.php` —
- `is_ipv4_mapped(string $address): bool` (`::ffff:0:0/96` membership)
- `is_nat64(string $address, string $prefix = '64:ff9b::/96'): bool`
- `ipv4_to_mapped(string $v4): string` → `::ffff:a.b.c.d`
- `mapped_to_ipv4(string $v6): string` (rejects non-mapped input)
- `ipv4_to_nat64(string $v4, string $prefix = '64:ff9b::/96'): string`
- `nat64_to_ipv4(string $v6, string $prefix = '64:ff9b::/96'): string`
**Drawer:** New IPv6-tab drawer "IPv4-mapped / NAT64". Single bidirectional input — paste an IPv4 or v4-mapped/NAT64 IPv6, get all forms back. Custom NAT64 prefix accepted in an Advanced disclosure (default `64:ff9b::/96`).
**API:** `POST /api/v1/mapped6` (and bulk coverage from item B).
**Tests:** PHPUnit (round-trip every form, custom NAT64 prefix at /96, error cases for non-mapped input, edge cases like `::ffff:0:0` and `::ffff:255.255.255.255`); Playwright drawer test; OpenAPI Spectral pass.

## Risks

1. **Per-tool URL routes (#7) is the highest-blast-radius item.** Touches `index.php` routing, `.htaccess` rewrite, `request.php` query parsing, `app.js` shareable-URL emission, every iframe consumer, every docs deep link. **Mitigation:** keep `?tab=&tool=` URLs working as accepted input (no auto-redirect that would break iframes). Add Playwright cases asserting both forms route identically.
2. **`request.php` globals refactor (#5)** changes every tool's render path. **Mitigation:** full Playwright pass after the refactor; PR is gated on green Docker test run before any subsequent PR begins.
3. **Twelve PRs vs v3.3.0's seven.** Realistically 2-3 weeks of focused work. **Mitigation:** sequenced so each PR is independently mergeable; if scope pressure lands mid-release, the natural cut points are #7 (defer URL routes to v3.5.0) or one of #8/#9 (new tools).
4. **Refactor PRs (#3, #4, #5, #6) introduce no user-visible behaviour change.** Risk is regressions in tools that aren't covered by Playwright. **Mitigation:** audit Playwright coverage before #5 lands; add cases for any uncovered tool before merging #5.
